# 微信读书页改版与功能规划

## 产品定位

Olib 是找书、管理本地图书、发现内容、利用阅读数据的入口。阅读行为留在微信读书；Olib 不做微信读书正文阅读器，不读取或展示付费公众号正文，也不批量保存文章/书籍正文。

微信读书所有功能统一使用扫码建立的移动端会话，通过 Flutter 客户端直连对应接口。接口路径和分页适配参考本地 `weread-omni` 实现。使用的阅读时长字段均以秒计。

## 本轮四项能力

| 功能 | 入口与交互 | 数据来源 | 顺序 |
| --- | --- | --- | --- |
| 公众号与文章搜索 | 微信读书搜索页提供“图书 / 公众号 / 文章”类别。结果展示接口返回的标题、来源及可用摘要；点开时使用返回的 `deepLink`。 | 移动端 `/store/search`：图书 `scope=10`、公众号 `scope=2`、文章 `scope=4`。 | 已接入 |
| 精美阅读报告 | 选择本周、本月或本年，预览海报，切换视觉主题，导出 3:4 PNG，并通过系统分享面板分享。 | 移动端 `/readdata/detail`；只使用实际返回的数据。 | 已接入 |
| 导入个人图书 | 在 Olib 书架中快速选择已下载的文件，或从本机选文件；显示上传进度和结果。 | 移动端临时 COS 凭据、手机直传、`/cos/notify`。 | 已接入 |
| AI 问书 | 详情页展示建议问题，也可输入自己的问题。 | 移动端 `ai.suggest/askBook`。 | 已接入 |

AI 回答使用本地 `widgets/weread_markdown_answer.dart` 排版常见 Markdown：标题、段落、强调、列表、引用、代码块、表格及 HTTP(S) 链接。流式回答尚未闭合代码围栏时仍可阅读；回答与代码都可复制，链接仅在用户点击时用系统应用打开。图片语法不会自动加载远程图片。未引入新的渲染依赖。

### 阅读报告的第一版

- 画布采用 3:4 竖版，暖纸张和深绿夜读两套主题，与现有 Olib 视觉统一。内容分为标题、核心数字、时间趋势、可选的“本期读得最多的一本书”和来源/周期落款。
- 核心数字取 `totalReadTime`、`readDays`、`dayAverageReadTime`；趋势用 `readTimes`。`readLongest` 或 `readStat` 缺失时直接隐藏对应模块，不推算连续打卡或虚构读完本数。`readTimes` 只绘制趋势，不替代总时长。
- 分享前允许用户隐藏“读得最多的书”和自填展示名称；默认不展示书名、头像、账号 ID、划线原文或付费内容。海报标注统计周期和“数据来自微信读书，海报由 Olib 制作”，避免暗示官方合作。
- 本地生成 PNG，复用项目已有的 `RepaintBoundary`、`ShareUtils`、`share_plus`。系统分享面板可选择小红书；Olib 不自动代用户发布。

### 搜索公众号内容的边界

搜索页保留关键词历史，类别切换后沿用当前关键词；公众号与文章结果单独排版，不套用图书评分和封面布局。只展示搜索接口提供的元数据。文章点击优先使用接口返回的跳转链接；无链接时不拼接或猜测 URL。可以搜索和打开公众号内容，但不在 Olib 中抓取全文，也不调用 weread-omni 的 `paidContent`。

## 暂不接入的 weread-omni 能力

- 书架置顶、私密、在读/读完标记及增删，划线的新增/样式修改/删除、点评的发表/编辑/删除：当前用户目标集中在导入、提问与报告，先不增加维护型操作。
- 公众号订阅管理、Feed/RSS/Atom 生成、文章归档/批量导出：搜索与跳转已覆盖本轮发现需求。
- 付费文章正文读取、正文抓取、微信读书站内阅读器：不符合本项目定位。
- CLI 多账号管理、`doctor` 和本地内容库：属于命令行工作流，移动端只保留必要的连接状态和退出能力。
- 付费内容接口与正文下载：不接入。

## 连接方式和实施边界

所有微信读书页面复用同一扫码会话。Android 以 Keystore AES-GCM 加密后存放应用私有 SharedPreferences；iOS 使用 Keychain 的 `AfterFirstUnlockThisDeviceOnly`。旧 API Key 入口与网关客户端已移除；用户设备中已有的旧 Key 不自动删除。真机验证表明微信要求使用扫一扫摄像头识别该二维码，同机打开确认链接不能完成登录；需把二维码发送到另一块屏幕，再用手机微信扫一扫。扫码仍以轮询确认结果判断是否登录成功；没有第二块屏幕时暂时无法完成连接。

移动端 Dart 客户端直接访问微信读书移动接口，不在 Flutter 内运行 Node，也不需要新建后端。个人图书导入仅处理用户主动选择的本地文件：Olib 书架入口仅列出已有本地下载文件的收藏书；也可使用本机文件选择器。限制 EPUB/PDF/MOBI/TXT/AZW3、200 MiB；先取临时 COS 凭据，使用 COS V5 签名直传，再调用 `/cos/notify`。超时或通知结果不确定时不自动重试，提示用户先检查扫码账号的书架。临时 COS 凭据只保留在本次上传内存中。

### 实现入口与人工验收

- 微信读书首页：阅读报告、导入个人图书；搜索页：图书/公众号/文章类别；本地下载列表：单个完成文件的“导入到微信读书”；上传页：从 Olib 书架快速选已下载图书；书籍详情：“AI 问这本书”；设置页：扫码连接与退出。
- 阅读报告固定 3:4 海报，周/月/年使用 `totalReadTime`、`readDays`、`dayAverageReadTime` 和 `readTimes`，可切换两套主题、自填显示名称和决定是否显示读得最多的书；PNG 通过系统分享面板导出。
- 扫码连接、临时 COS 上传凭据、通知和 AI 接口依赖微信读书移动接口，可能随上游改变。真机已确认同机直接打开确认链接不可用；仍需验证另一设备扫码、会话刷新、导入小文件与大文件、取消及结果不确定提示、AI 建议问题和回答。项目未配置真实账号做自动化接口验证；本轮按用户要求不跑测试。主要 Dart 文件的静态检查曾通过，但本次静态分析在 Windows 的 Dart perf 临时文件删除处失败；Android 编译在本机被 Gradle 的 `Unable to establish loopback connection` 阻断；iOS 需在 macOS 真机/模拟器上编译。
